# One chat photo

Discover the live tools and schemas first; these names grant no access. Follow the [photo workflow](../SKILL.md#send-one-photo-with-words), including its one complete review and next-message yes. No direct or custom-group photos, photo-only messages or raw media URLs.

| Operation ID | Inputs besides `catalogVersion: 1` | Result and meaning |
| --- | --- | --- |
| `chat-upload-start` | `body: { kind, channelId, fileName, contentType, size }`; kind `team` or `staff`, channel ID 1–128 characters, trimmed filename 1–255, MIME `image/jpeg` or `image/png`, positive whole-byte size at most 5,242,880 | `{ uploadId, uploadUrl, expiresAt }`; one current Team/Staff chat where the caller is team staff. `expiresAt` is the five-minute send deadline. The single-object no-overwrite Storage address lasts two hours; never repeat it in replies or retain it in notes/files, except the temporary script handoff |
| `request-key-new` | Input `{}`, no catalog version | One UUID; use unchanged as this intended send's `messageId` |
| `chat-message-send` | `body: { kind, channelId, messageId, text, uploadId }`; same Team/Staff chat, original message UUID, trimmed nonblank text at most 5,000 characters, the returned upload ID | `{ outcome: "published" \| "unknown", messageId }`; published means sent, not read or device delivery. Unknown or lost answers stop writes; no automatic resend, replacement key or history scan |

Write the start response to a private temporary JSON file only for the script handoff, pass its file path rather than the address on the command line, and delete it immediately after the script returns, whatever the result. The uploader uses `uploadUrl` as the PUT destination and checks `expiresAt` before starting. It reads one chosen local JPEG/PNG, refuses over 5 MiB or 2048 px on either edge, and refuses a detected type that does not match the reservation's `.jpg` or `.png` ending before any PUT. It sends the exact bytes once with the detected `Content-Type` and `x-upsert: false`, only to Hype's HTTPS staging Storage path; no redirects, proxies or retries. It prints only `uploaded` (exit 0), `refused: <short reason>` (exit 1), or `unknown` (exit 2), never the response, address or remote error body. Unexpected failures once the request starts stay unknown. Header checks are not full decoding or orientation checks: save the photo upright first; Hype validates it again before publication. Uploading alone sends no message.

The tool result itself contains the signed address; do not promise to remove it from the host's transcript. Never repeat, quote, summarize or display the address in replies to the person, saved notes, progress records or any file kept; only the temporary handoff file above is allowed. A lost `chat-upload-start` answer stops writes without an automatic restart; a new start needs a fresh complete review and next-message yes, keeping the original `messageId`. Once `uploadId` is known, any supported send repeat must keep that same `messageId`, `uploadId` and exact approved binding after a fresh complete review and next-message yes, never a new upload or key. A consumed receipt stays bound to that message even after failure. Never repeat an expired receipt or confirmed publication.
